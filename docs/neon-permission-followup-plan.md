## 2. 已确认的设计决定

用户已选择：**只读诊断仅输出脱敏 JSON，删除诊断工具的自动文件保存；正式基线报告保留。**

具体行为：

- 诊断 CLI 正常成功时 stdout 仅输出一个完整 JSON 对象和结尾换行。机器读取统一使用 `node scripts/neon-permission-audit.mjs --expected-database <已核对数据库名>`，避免包管理器脚本启动提示混入 stdout；package 别名可保留，但不把普通 `pnpm run` 的整个输出承诺为纯 JSON。
- 运行失败时 stderr 输出脱敏错误，退出码非零，不输出成功 JSON。
- `--help` 保留正常帮助文本，且不读取凭据、不连接数据库。
- 删除诊断入口的 `--report` 参数、默认临时目录、`report_path` 字段及报告文件写入函数；旧参数明确报错，并在数据库连接前退出。
- 诊断程序不创建文件、目录或替代性日志。不要用 shell 重定向、子进程或另一包装脚本默认恢复自动保存。
- 如后续确需人工保留脱敏结果，由明确的独立操作处理；本任务不提供自动导出能力。
- 正式 `neon-baseline` 的报告、权限验证、原子候选流程和工具 SHA 绑定全部保留。

这一调整是减少诊断功能范围，不是将 F6 降级、隐藏测试或放宽临时路径规则。诊断当前没有其他脚本消费者，Gate 1 只调用对应测试；因此无需引入跨平台目录句柄、新依赖或平台专用路径实现。

## 8. 验收材料与参考

最终材料只保留有效结果：已确认根因、最终文件范围、真实测试/审查结果、候选与工具 SHA、远程前后状态、未执行项。逐次聊天、原始诊断输出和临时执行日志不复制进仓库。

Node 官方文档说明，先检查路径再打开文件存在状态被其他进程改变的间隙；本次采用删除诊断文件写入路径的方案，而不是宣称路径检查已能抵御所有目录替换。[文件系统文档](https://nodejs.org/docs/latest-v24.x/api/fs.html#fspromisesaccesspath-mode)

stdout 可能异步完成，`process.exit()` 会截断未完成输出；因此 JSON 输出测试须验证自然退出时的完整性。[进程文档](https://nodejs.org/docs/latest-v24.x/api/process.html#processexitcode)
