- **为什么这是硬前置**：`docs/neon-vercel-baseline-runbook.md:140` 规定「预检模式要求当前分支和
  `HEAD` 精确等于冻结候选 commit；**写入模式要求当前 `HEAD` 精确等于已批准的工具 SHA**」。
  按现状直接进入写入模式会被预检拒绝。
- **详细步骤**：
  1. 确认新的目标 HEAD（本窗口开始时的 `git rev-parse HEAD`）。

     `database/releases` 的 V1/V2 数据包）。

- **验收标准**：新工具 SHA 已在 `docs/decisions.md` 或 runbook 中记录并标注「已批准」；
  执行闭包 26 条路径 `git status` 干净；数据包与迁移校验和与冻结值逐字一致。

  必须**共同**验证：`btree_gist` 可用、无 Neon 专有 API/扩展依赖、迁移/发布/权限/查询/性能一致。
- **验收标准**：该声明写入文档；跨环境一致性清单列出具体待验项。

**执行结果（2026-09-25，详见 `docs/neon-vercel-baseline-runbook.md` 第 9 节）**：隔离性声明已写入；一致性清单列出 **8 项**，其中 **2 项已在仓库侧核实**、**6 项标注「Neon 待验」**。

**本轮最有价值的发现（第 8 项）**：本项目使用**会话级** `pg_advisory_lock` / `pg_advisory_unlock`（`migrate.ts:58`、`publish-release.ts:117`、`activate-and-materialize.ts:33`），而 **Neon 的池化端点是 PgBouncer 事务模式，不支持会话级 advisory 锁**。设计上风险已被隔离（三个写入入口走管理直连，`app_reader` 的池化连接只做只读查询与 REPEATABLE READ 事务），但**部署时必须确认三个写入入口的连接串是直连而非池化**——若误用池化端点，advisory 锁会**静默失效且不报错**，这是把「本地通过」误当成「Neon 通过」最可能的路径。

另核实：`btree_gist` 不只是被创建，而是在 `0001_gate1_schema.sql:100` 有 `EXCLUDE USING gist` 的**实际使用**，因此是真实依赖；全仓无 `@neondatabase/serverless` 或其他 Neon 专有驱动（`packages/db` 仅用 `pg` 8.23.0）。

- **难度**：低
- **思考强度**：`medium`
- **分级与角色**：L1，`slice_owner`（terra / medium）

## 8. 关键事实与陷阱（承接前一份，供后续会话避免重复试错）

**本机环境**（详见 `docs/handoff-2026-09-25.md` §7 与工作区记忆）：

- `git push` 在本会话会挂起，根因是凭据助手 `git-credential-manager.exe` 在非交互环境下卡住。
  解法（不改全局配置）：
  `git -c credential.helper= -c 'credential.https://github.com.helper=!gh auth git-credential' push origin <branch>`
- 本机网络走本地代理 `127.0.0.1:59023`，会瞬态返回 `CONNECT tunnel failed, response 502`，
  重试即可；`api.github.com` 与 `github.com` 的可用性可能不同。
- Bash 通道禁止出现字面字符串 `PowerShell`（安全过滤会拦截整条命令）；多行提交消息写入文件后
  用 `git commit -F <file>`。
- `gh api` 的端点参数不能带前导斜杠（Git Bash 会重写为文件路径）。
- `pnpm` 不可直接调用，改用 `node node_modules/<pkg>/...`；`scripts/*.test.mjs` 是 Node 原生测试，
  用 `node --test <file>`。
- 会话内 Node 脚本以 `spawnSync`/`execSync` 调用外部命令会恒返回 `EBUSY`，
  因此 `run-db-integration-tests.mjs` 与 `verify-gate1-isolated.mjs` 必须由用户终端执行。
- `git commit` 会打印 `error: task 'geometric-repack' failed`（`refs/codex/turn-diffs/checkpoints/...`
  指向缺失对象），**提交本身成功**，可忽略。

**项目约束**（以 `docs/development-roadmap.md` §1.1 与 `docs/decisions.md` 为准，本文档仅作提示）：

- 数据库权限拆分为 `schema_migrator`、`data_publisher`、`app_reader` 三个最小权限角色，
  公开运行环境只持有 `app_reader`。
- 所有页面查询统一归一化为 V1.0 的 `QuestionType + AnalysisScope`；浏览器查询统一进入
  `POST /api/v1/query`，服务端渲染直接复用查询服务函数，不通过内部 HTTP 回环。
- 服务端硬超时 10 秒，超时用 HTTP 504 独立基础设施错误，不修改 V1.0 业务错误联合类型。
- 第一闸门全部 SQL 迁移**只增不减**。
- 合并 `main` **不**自动发布公开测试环境。
- 应用启动与数据库访问工具**不得**自动同步正式结构。
