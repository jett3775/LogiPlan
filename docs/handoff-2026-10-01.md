2. **授权第二段（远程写 E1—E5：Neon 激活 + Vercel 部署）？**（推荐：**先只授权到 E2**，
   即在 E1 激活前再确认一次。激活会切换活动发布，是不可逆性最高的一步。）
3. **重新冻结并批准新的工具 SHA？**（推荐：批准。**这是硬前置**——写模式要求 HEAD 精确等于
   已批准的工具 SHA，而冻结候选 `0229755a…` 已落后 **18 个提交**，按现状会被预检直接拒绝。）
4. **授权 GitHub 仓库设置操作（P5 秘密扫描启用与验证）？**（推荐：授权。属仓库设置，
   不涉及代码改动，但属外部操作。）

## 8. 关键事实与陷阱（承接前一份，供后续会话避免重复试错）

**本机环境**（详见 `docs/handoff-2026-09-25.md` §7 与工作区记忆）：

- `git push` 在本会话会挂起，根因是凭据助手 `git-credential-manager.exe` 在非交互环境下卡住。
  解法（不改全局配置）：
  `git -c credential.helper= -c 'credential.https://github.com.helper=!gh auth git-credential' push origin <branch>`
- 本机网络走本地代理 `127.0.0.1:59023`，会瞬态返回 `CONNECT tunnel failed, response 502`，
  重试即可；`api.github.com` 与 `github.com` 的可用性可能不同。
- Bash 通道禁止出现字面字符串 `PowerShell`（安全过滤会拦截整条命令）；多行提交消息写入文件后
  用 `git commit -F <file>`。
- `gh api` 的端点参数不能带前导斜杠（Git Bash 会重写为文件路径）。
- `pnpm` 不可直接调用，改用 `node node_modules/<pkg>/...`；`scripts/*.test.mjs` 是 Node 原生测试，
  用 `node --test <file>`。
- 会话内 Node 脚本以 `spawnSync`/`execSync` 调用外部命令会恒返回 `EBUSY`，
  因此 `run-db-integration-tests.mjs` 与 `verify-gate1-isolated.mjs` 必须由用户终端执行。
- `git commit` 会打印 `error: task 'geometric-repack' failed`（`refs/codex/turn-diffs/checkpoints/...`
  指向缺失对象），**提交本身成功**，可忽略。

**项目约束**（以 `docs/development-roadmap.md` §1.1 与 `docs/decisions.md` 为准，本文档仅作提示）：

- 数据库权限拆分为 `schema_migrator`、`data_publisher`、`app_reader` 三个最小权限角色，
  公开运行环境只持有 `app_reader`。
- 所有页面查询统一归一化为 V1.0 的 `QuestionType + AnalysisScope`；浏览器查询统一进入
  `POST /api/v1/query`，服务端渲染直接复用查询服务函数，不通过内部 HTTP 回环。
- 服务端硬超时 10 秒，超时用 HTTP 504 独立基础设施错误，不修改 V1.0 业务错误联合类型。
- 第一闸门全部 SQL 迁移**只增不减**。
- 合并 `main` **不**自动发布公开测试环境。
- 应用启动与数据库访问工具**不得**自动同步正式结构。
