## 3. 关键决策与发现（必读，按重要性排序）

### 3.1 发布门：改用 Vercel 原生「staged production」，不要自建 GitHub Actions 工作流

**这是本轮最重要的结论**，直接改变 runbook §10.5 的设计。

冻结要求是「合并 `main` **不**自动发布公开测试环境；受保护 Production 工作流必须由人工批准，并绑定
已通过检查的具体提交 SHA、迁移清单和数据包校验和」。查证 Vercel 官方文档后确认，**这条要求可以完全
由 Vercel 原生功能满足**：

- 在 **Settings → Environments → Production → Branch Tracking** 关闭
  **「Auto-assign Custom Production Domains」** 后，推送到生产分支只产生 **`Staged`** 状态的生产部署
  （已按 production 环境变量构建，但**不对外服务**），必须**人工 Promote** 才变成 `Current`。
- **promote 不触发重建** → **验证过的构建就是上线的构建**。这比 promote preview 更强（后者会
  "complete rebuild with production environment variables"）。
- 部署状态机：`Staged` → `Promoted` → `Current`；**已 Promoted 过的部署不能再次 promote，只能 rollback**。
- **回切（D-155）**：Instant Rollback（`vercel rollback` / 面板）或 Promote 另一个 Staged 部署。

**为什么优于自建工作流**：自建需要在 GitHub Actions 里跑发布，就得把 Vercel token 放进 GitHub secrets
——**一个新的凭据面**，且与本项目「Vercel 不持有数据库管理凭据」的谨慎风格不一致。此外
**GitHub Environment 的保护规则管不到 Vercel 自己的 Git 集成部署**，原设计有隐藏漏洞。

**附带效果**：一旦关闭 auto-assign，**合并 `main` 就变成安全的**——它只产生不对外服务的 Staged 构建。
「不敢合并 main」这个僵局随之解开。

### 3.2 会话级 advisory 锁不能用 Neon 池化端点

本项目用**会话级** `pg_advisory_lock` / `pg_advisory_unlock`（`migrate.ts:58`、
`publish-release.ts:117`、`activate-and-materialize.ts:33`），只由迁移 / 发布 / 激活三个入口使用，
**必须走管理直连**。Neon 的池化端点是 PgBouncer 事务模式，**不支持会话级锁**，误用会**静默失效且不报错**
——这是把「本地通过」误当成「Neon 通过」最可能的路径。

### 3.3 平台配额的四项关键缺口

1. **Vercel Hobby 运行时日志仅保留 1 小时**（构建日志永久）→ **无法**满足 D-139 的 14 天明细 / 90 天聚合，
   必须另行实现。
2. **Neon Free 监控指标仅保留 1 天** → 90 天聚合不能依赖它。
3. **Neon Free 闲置 5 分钟即挂起且不可关闭** → 冷启动不可避免，**不得宣称生产级可用性**。
4. **Vercel Hobby 并发部署 = 1** → 预览部署串行。

**澄清**：Hobby 的 Function 执行时长在 Fluid compute 下为 **300 s**，远大于查询契约的 10 s 硬超时，
**不构成冲突**；不要把「Hobby 默认 10 s」当现状（那只适用于 2025-04-23 之前部署且未启用 Fluid compute 的项目）。

### 3.4 新增的启动校验会改变部署行为（**部署前必须知道**）

`readWebRuntimeDatabaseUrl()` 现在会校验 `DATABASE_URL` 的**用户名必须是 `app_reader`**。因此：

- **Production 构建时角色不对 → 构建直接失败**（以前是静默通过）。
- 反过来说，**Production 构建成功即证明角色正确**——不必去抠 Vercel 的掩码值。
- **池化端点无法自证**（未做该校验，因为本地与 CI 用非池化的本地 PostgreSQL），仍需人工确认。

## 6. 环境陷阱（供后续会话避免重复试错）

- `git push` 会因凭据助手 `git-credential-manager.exe` 在非交互环境挂起。解法：
  `git -c credential.helper= -c 'credential.https://github.com.helper=!gh auth git-credential' push origin <branch>`
- 本机网络走本地代理 `127.0.0.1:59023`，**会持续数分钟到十几分钟地返回
  `CONNECT tunnel failed, response 502`**（推送曾需 15 次尝试、14 次尝试）。**只重试，不要改配置**；
  `gh api`（api.github.com）通常不受影响。**直连不可行**（`github.com:443` 连不上）。
- Bash 通道禁止出现字面字符串 `PowerShell`（安全过滤拦截整条命令）；多行提交消息写入文件后用 `git commit -F`。
- `gh api` 端点参数**不能带前导斜杠**（Git Bash 会重写为文件路径）。
- `pnpm` 不可直接调用：用 `node node_modules/<pkg>/...`（prettier / eslint / vitest）。
  **`tsc` 用 `node_modules/.bin/tsc`**（TS 7.0.2；`node_modules/typescript/bin/tsc` **不存在**）。
  apps/web 类型检查需先 `apps/web/node_modules/.bin/next typegen`。
- 会话内 Node 脚本以 `spawnSync`/`execSync` 调外部命令**恒返回 `EBUSY`**，故
  `run-db-integration-tests.mjs` 与 `verify-gate1-isolated.mjs` **必须由用户终端执行**。
- `scripts/*.test.mjs` 是 Node 原生测试，用 `node --test <file>`（不在 vitest 的 include 内）。
- **`vitest.config.ts` 的 `coverage.include` 是显式白名单**：新增源文件默认**不进覆盖率分母**。
- `git commit` 会打印 `error: task 'geometric-repack' failed`（`refs/codex/turn-diffs/checkpoints/...`
  指向缺失对象），**提交本身成功**，可忽略。
- **Vercel 的 Preview 部署是公开可达的**（每次推送自动生成），但**本会话无法访问**（代理拦截）。
