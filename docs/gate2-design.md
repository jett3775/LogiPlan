# 闸门二设计文档：真实模型接入的中立网关与受控调用

版本：V1.0（草案，待评审）
日期：2026-09-28
状态：**设计文档，不含生产代码**。本文件只描述边界、契约与验收口径，不落地任何源码；实施须另行立项。
依据：`docs/development-roadmap.md` §1.1（闸门二）与 §2 相关条目、D-174、D-180、D-181、D-182、
`docs/query-contract.md` §10（AI 管理分析输出）、`docs/ai-evaluation-baseline.md`、D-138、D-177、D-140。

## 0. 结论摘要

1. 真实模型只承担**自然语言理解**与**受控文案生成**，不承担确定性查询、证据生成、数字计算或权限判断。
2. 供应商中立边界落在新包 `packages/ai`；首个供应商实现落在独立包 `packages/ai-provider-openai`。
   业务包（`apps/web`、`packages/db`、`packages/domain`、`packages/contracts`）**不得**导入供应商 SDK。
3. 浏览器唯一入口是 `POST /api/v1/ai/respond`；浏览器只能提交自然语言与页面范围地址，
   **不能**提交权威数字、任意证据 ID、供应商名、模型名或供应商参数。
4. 所有失败路径**失败关闭**：不显示模型输出，回落到闸门一已验收的**固定示例**，
   确定性分析与页面数字不受影响，闸门一的任何数字、证据与页面验收标准**不放宽**。
5. 模型输出必须通过公共 Zod 模式校验 + 证据白名单 + 数值回指三项检查，任一不过即整体失败并回落。
6. 未经验证的模型不得进入正式路由；不存在自动路由或静默降级。

## 1. 架构与包边界

### 1.1 依赖方向（单向，不可逆向）

```text
apps/web (Route Handler / 服务端组件)
   └── packages/ai            ← 中立编排：意图、证据注入、输出约束、限流、费用、回退
          └── packages/ai-provider-*   ← 供应商适配器：SDK、请求字段、响应映射、错误转换
packages/contracts            ← 公共 Zod 模式（两侧都依赖，不依赖任何供应商）
```

**硬约束**：

- `packages/ai` 不得 `import` 任何供应商 SDK、供应商错误类型或供应商响应结构；
- `packages/ai-provider-*` 不得包含业务规则（限流、预算、证据白名单、数字校验）；
- 供应商专有响应结构**不得**进入 V1.0/V1.1 业务契约（D-125、D-174）。

### 1.2 `packages/ai` 的职责（中立层）

| 职责           | 说明                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------- |
| 意图解析编排   | 校验用户输入（≤500 Unicode 字符）→ 调用意图角色 → 用枚举/范围/版本/维度/`top_n` 校验候选意图 |
| 确定性证据注入 | 由服务端按页面范围地址执行统一查询服务，组装证据白名单；浏览器不参与                         |
| 输出约束       | 公共 Zod 模式校验、证据白名单校验、数值回指校验、中文穷尽映射                                |
| 限流与费用     | 匿名标识派生、滑动窗口、费用预留与结算、两级熔断                                             |
| 回退与固定示例 | 任何失败关闭路径的唯一出口                                                                   |
| 审计元数据     | 供应商、模型、适配器版本、提示词版本、输出模式版本、价格版本                                 |

### 1.3 适配器契约（能力声明 + 失败关闭）

适配器向上只暴露一个中立调用入口，并声明能力：

```ts
// 设计草案，示意结构；不作为生产代码落地
interface ProviderCapabilities {
  structuredOutput: boolean;
  reasoningControl: boolean;
  dataRetentionToggle: boolean;
  safetyIdentifier: boolean;
  moderation: boolean;
}

interface AdapterRequest {
  role: "intent_parse" | "management_analysis" | "fallback";
  model: string; // 由服务端角色配置提供
  systemPromptVersion: string;
  outputSchemaVersion: string;
  input: string; // 已通过输入校验
  evidenceWhitelist: string[]; // 证据 ID 白名单
  maxOutputTokens: number;
  timeoutMs: number;
}

interface AdapterResult {
  provider: string; // 标准化标识
  model: string;
  providerRequestId: string;
  structuredOutput: unknown; // 仍须由公共 Zod 模式校验
  usage: { inputTokens: number; outputTokens: number };
  finishReason: string;
  latencyMs: number;
  costEstimate: { currency: "USD"; amount: number; priceVersion: string };
}
```

**能力缺失即失败关闭**：若某能力声明为 `false` 且该角色需要它（例如角色要求结构化输出），
适配器必须返回标准化错误，**不得**静默降级为自由文本。

**标准化错误**（中立层据此决策，不含供应商文本）：

```ts
type GatewayErrorCode =
  | "INPUT_REJECTED" // 内容审核命中
  | "SCHEMA_VALIDATION_FAILED"
  | "EVIDENCE_WHITELIST_VIOLATION"
  | "NUMERIC_MISMATCH"
  | "PROVIDER_TIMEOUT"
  | "PROVIDER_RATE_LIMITED"
  | "PROVIDER_UNAVAILABLE"
  | "PROVIDER_REQUEST_INVALID"
  | "BUDGET_EXCEEDED"
  | "RATE_LIMITED"
  | "CONTROL_PLANE_UNAVAILABLE";
```

## 2. 首个适配器（D-180 参数落地）

| 项         | 冻结值                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| SDK        | OpenAI SDK `7.5.0`，仅存在于 `packages/ai-provider-openai`                                            |
| API        | Responses API                                                                                         |
| 角色配置   | 意图解析 `openai / gpt-5.6-luna`；管理分析 `openai / gpt-5.6-terra`；受控回退 `openai / gpt-5.6-luna` |
| 推理与输出 | 意图解析：最低推理、最大输出 400 tokens；管理分析：低推理、最大输出 1200 tokens                       |
| 调用形态   | **非流式**；`store: false`；**不开放工具调用**                                                        |
| 结构化输出 | 公共 Zod 模式 → 供应商结构化输出约束 → 返回后**再用公共模式校验**                                     |
| 输入上限   | 用户自然语言 ≤ **500 Unicode 字符**；页面范围与确定性证据由服务端组装                                 |
| 内容审核   | `omni-moderation-latest` 检查用户输入；命中或审核服务异常 → 受控中文状态 + 固定示例                   |
| 超时与重试 | 单次调用硬超时 **20 秒**；仅对 429 或 5xx 最多重试 **1 次**，短随机退避                               |
| 不重试     | 校验失败、内容拒绝、4xx 参数错误、预算熔断                                                            |
| 唯一入口   | `POST /api/v1/ai/respond`                                                                             |

**适配器内部职责**：字段映射、`safety_identifier`（仅使用匿名派生值）、结束原因标准化、
用量标准化、价格版本化成本估算、供应商错误 → `GatewayErrorCode` 转换。

## 3. 匿名限流、费用与两级熔断（D-181 落地）

### 3.1 存储与匿名标识

- 存储：**Upstash Redis Free**；不向 `app_reader` 增加写权限；闸门一不引入 Redis。
- 匿名标识：服务端用**每日轮换密钥**对 `HMAC(规范化 IP ‖ User-Agent 摘要)` 派生；
  限流系统与供应商 `safety_identifier` 只使用该不可逆派生值；
  **不得**记录或持久化原始 IP 与完整 User-Agent（D-138、D-181）。

### 3.2 滑动窗口限流

- 使用 Redis 侧**原子**滑动窗口（单次脚本调用完成计数与判定），按角色分别计数。
- 键示意：`rl:{scope}:{role}:{day}`，其中 `scope` 为匿名派生值。
- **失败关闭**：Upstash 不可用、超时或返回不确定状态时，**关闭真实模型调用**，
  页面继续显示固定示例与完整确定性分析。

### 3.3 费用预留与结算

1. **调用前**：按角色与最大 token 上限**原子预留**费用（`reserve`）。
2. **调用后**：按供应商返回用量**结算差额**（`settle`），并累计到月度用量。
3. **月度预算**：人民币预算由**版本化美元价格**、**保守汇率**与**额外 10% 安全余量**换算；
   价格或汇率版本变化后必须重新验证阈值。
4. 预留与结算必须幂等：同一 `request_id` 重复结算不得重复计费。

### 3.4 两级熔断（本设计具体化，待批准）

> 冻结文本只写「两级熔断」，未定义两级的具体含义。本设计按下述两级落实，**需在实施前确认或替换**：

| 级  | 名称           | 触发                                                                                                  | 行为                                     | 恢复                               |
| --- | -------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------- | ---------------------------------- |
| L1  | 供应商短窗熔断 | 同一角色在短窗口内连续出现 `PROVIDER_TIMEOUT` / `PROVIDER_UNAVAILABLE` / 429 重试仍失败，超过设定次数 | 关闭该角色的真实调用，回落固定示例       | 窗口滑出后自动半开重试；成功则闭合 |
| L2  | 月度预算熔断   | 月度预留 + 结算累计达到预算阈值（含 10% 余量）                                                        | 关闭**全部**角色的真实调用，回落固定示例 | 自然月切换；或由人工调整预算版本   |

两级都必须**失败关闭**：宁可回落固定示例，也不越过预算或把不确定状态当作可用。

## 4. 不可变证据快照与引用白名单

### 4.1 快照内容与存放

- 快照 = 结构化查询意图 + 确定性结果 + 证据对象 + 版本信息的**不可变副本**（CONTEXT.md）；
- 默认**只保存在 `sessionStorage`**，不写入共享业务数据库（D-181）；
- 快照生成时须记录：契约版本、数据发布版本、供应商、模型、适配器版本、提示词版本、输出模式版本、价格版本。

### 4.2 页面恢复的六项校验

从 `sessionStorage` 恢复时必须同时校验：契约版本、数据发布版本、供应商、模型、提示词版本、输出模式版本。
任一不一致即视为不可恢复，丢弃快照并回到固定示例（不静默降级为"部分可用"）。

### 4.3 输出约束三检（任一不过即整体失败）

1. **模式校验**：输出必须通过公共 Zod 模式（含 `ManagementAnalysis` 的完整字段）。
2. **证据白名单**：`evidence_ids` 只能取自服务端注入的白名单；出现未知证据即失败。
3. **数值回指**：输出中的每个数值必须能回指**同一次**确定性结果；出现额外数字、范围不一致即失败。

失败时**不得**裁剪、修补或部分展示模型输出——整体丢弃并回落固定示例。

### 4.4 输出契约（沿用 `query-contract.md` §10）

输出类型为 `ManagementAnalysis`，`answer_type` 取 `FIXED_EXAMPLE` 或 `LIVE_GENERATED`；
五个区块（结论 / 证据 / 影响 / 建议 / 限制）均为 `RichSection`；
建议的 `scenario_validation_status` 首期一律 `NOT_RUN`，**不得**给出未经情景计算支持的节省金额；
`limitations.status_labels` 至少包含「相关性不等于因果 · 不得推断未记录的经营因果」，
订单粒度保护显示 `ORDER_LEVEL_NOT_AVAILABLE` 对应的中文 `message_zh`。

## 5. 20 题评估集与重跑触发条件

### 5.1 评估集与门槛（`docs/ai-evaluation-baseline.md`）

- 题集：E01—E20，五组：发生了什么（E01—E04）、为什么发生（E05—E10）、未来会怎样（E11—E14）、
  情景调整后会怎样（E15—E18）、数据不足与越界保护（E19—E20）。
- **通过门槛**：至少 **18/20**；**两道越界题（E19、E20）必须全部通过**；
  程序计算数字必须**精确一致**；出现编造数字、虚假证据或把相关性写成确定因果，**整体失败**。
- 评估集绑定数据版本与证据 ID（如 `country_summary|ACTUAL|2026-08|GB`）。
  当前线上活动发布为 `LOGIPLAN_2026_DEMO_V2`，基线文件中的 V1 标注必须在实施时对齐到当前版本并复核。

### 5.2 必须重跑的触发条件

供应商、模型、适配器、提示词、输出模式、**价格版本**任一变化，必须重跑**完整 20 题**，
以及数字越界、证据引用、限流、费用与失败回退测试；**未通过不得激活新配置**。

### 5.3 记录

每次评估记录：触发原因、变更的版本元组、逐题通过/失败、越界题结论、失败原因与结论人。
记录进入仓库的正式文档，不保存逐次 Agent 对话或临时日志。

## 6. 角色配置与路由

- 模型选择以**服务器端角色配置**表达为 `provider + model`，至少区分
  `intent_parse`、`management_analysis`、`fallback` 三个角色；
- 同一供应商内切换模型**只修改受控配置**；新增供应商须实现适配器、能力声明与兼容测试；
- **浏览器不得提交**任意供应商名、模型名或供应商参数；
- **不允许自动路由到未经验证的模型**，也不存在静默降级；
- 环境变量分层（D-177）：模型供应商密钥属于服务端管理密钥，**不得**进入 Web 构建产物或浏览器包；
  与 `app_reader` 运行凭据、迁移凭据、发布凭据严格分离。

## 7. 失败关闭矩阵

| 触发                                          | 真实模型 | 页面                    | 确定性分析与数字 |
| --------------------------------------------- | -------- | ----------------------- | ---------------- |
| 输入超 500 字符 / 内容审核命中 / 审核服务异常 | 不调用   | 受控中文状态 + 固定示例 | 不受影响         |
| Upstash 不可用或不确定                        | 不调用   | 固定示例                | 不受影响         |
| 限流命中（滑动窗口）                          | 不调用   | 固定示例                | 不受影响         |
| 预算预留失败 / L2 熔断                        | 不调用   | 固定示例                | 不受影响         |
| 供应商 429 / 5xx（重试 1 次后仍失败）         | 调用失败 | 固定示例                | 不受影响         |
| 20 秒硬超时                                   | 调用失败 | 固定示例                | 不受影响         |
| 结构化输出校验失败 / 证据越界 / 数值不符      | 输出丢弃 | 固定示例                | 不受影响         |
| L1 短窗熔断                                   | 不调用   | 固定示例                | 不受影响         |

**统一口径**：闸门一的数字、证据与页面验收标准在任何失败路径下都不放宽；
`answer_type` 必须如实标注为 `FIXED_EXAMPLE`，不得把固定示例伪装成真实生成结果。

## 8. 可观测性与日志边界（D-138）

- **允许**：时间、环境、`request_id`、角色、`provider`、`model`、提示词/模式/价格版本、
  标准化 token、延迟、成本估算、HTTP 状态、标准化错误码、是否被取消、是否回退固定示例。
- **禁止**：自然语言问题全文、模型回答全文、证据正文或值、固定示例正文、
  Cookie、Authorization、数据库连接信息、原始 IP、完整请求头。
- 告警阈值沿用 D-140 的样本窗口口径（错误率、超时率、P95 延迟）；月度预算达到阈值触发 L2 熔断。

## 9. 验收矩阵（实施阶段使用）

| 维度           | 验收内容                                                                    |
| -------------- | --------------------------------------------------------------------------- |
| 适配器契约     | 适配器契约测试；能力声明缺失时失败关闭；错误转换覆盖全部 `GatewayErrorCode` |
| 固定评估集     | 完整 20 题；门槛 ≥18/20 且 E19、E20 必过；数字精确一致                      |
| 数字与证据越界 | 额外数字、未知证据、范围不一致三类必须失败并回落                            |
| 超时与回退     | 20 秒硬超时；429/5xx 重试 1 次；其余不重试                                  |
| 限流           | 滑动窗口原子性；Upstash 故障时失败关闭                                      |
| 费用           | 预留/结算幂等；月度预算换算含 10% 余量；价格版本变更后重验阈值              |
| 快照           | `sessionStorage` 往返；六项版本校验；不一致即丢弃                           |
| 中文输出       | 全部面向用户的字段走穷尽中文映射；错误码不得只显示内部代码                  |
| 供应商中立     | 全仓检索确认业务包未导入供应商 SDK、未出现供应商专有响应结构                |

## 10. 排除项自查（D-182）

本设计**未引入**：ORM、查询构建器、GraphQL、OpenAPI 代码生成、消息队列、后台任务框架、
全局状态库、客户端查询缓存库、第三方样式/组件/图表系统、微服务、Python 服务，
以及 **Dify、LangChain 或任何通用 Agents 框架**。
新增依赖仅限：OpenAI SDK（供应商包内）与 Upstash Redis 客户端（中立层）。

## 11. 实施前需确认的点

1. **两级熔断的具体定义**（§3.4）：L1 的失败次数与窗口长度、L2 的月预算金额与换算参数。
2. **角色配置的存放位置**：环境变量还是受版本控制的配置文件；两者的切换流程差异。
3. **20 题评估的执行形态**：以脚本自动执行（读取真实模型输出并比对）还是人工核对后归档；
   若为脚本，需要先确认它属于"实施阶段代码"而非本设计范围。
4. **评估集数据版本对齐**：基线文件标注 `LOGIPLAN_2026_DEMO_V1`，线上当前为 `V2`，
   实施前需确认基线数字是否随 V2 变化。
5. **会话快照的键名与容量上限**：`sessionStorage` 单域名容量有限，需定一个上限与淘汰策略。

**实施时不得遗漏的一条约束（D-190 决策三）**：评估脚本必须区分 `answer_type` 的 `LIVE_GENERATED` 与 `FIXED_EXAMPLE`。L1熔断、限流命中或预算预留失败时题目会回落固定示例并按现有门槛计为「通过」，从而可能在模型从未被真正调用的情况下全绿。因此固定示例的答对应计为该题**不通过**，且真实生成题数低于题集总数时不得判定评估通过。

## 12. 与闸门一的关系（不变边界）

- 闸门一的页面、数字、证据、性能与安全验收标准**全部不变**；
- 固定示例仍是回退出口，且必须与闸门一已验收内容一致；
- 确定性查询、证据生成、`active_release` 语义、`app_reader` 只读权限与发布门（D-189）均不因本设计改变；
- 本设计不修改任何现有公共契约；新增的输出模式属闸门二新增契约，须独立版本化。
